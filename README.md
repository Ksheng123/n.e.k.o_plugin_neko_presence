# 她的一天 (neko_presence)

> 她会记得你什么时候来，也会记得你什么时候走。
> 你安静了多久，她不说破，只在心里数着。

**当前版本 v0.7.0 · 持续更新中。**

她不提醒你睡觉，不催你休息，也不给你打分。她做的只有一件事：
安静地看着你今天的在场与离开，把它们攒成一段可以回头看的时光。

- ✅ 装上就工作，零配置、零输入
- ✅ Windows 原生信号只依赖标准库（`ctypes` 直调系统 API），不联网、无遥测、断网照常运行
- ✅ 非 Windows 平台自动改用宿主快照；拿不到信号时诚实标「没有记录」，不猜
- ✅ 不读屏幕内容、不读窗口标题、不读键盘内容
- ✅ 面板每 5 秒自行刷新；聊天里问 YUI，她用同一个口径回答（见「和 YUI 说话」）
- ✅ 自带「暂停记录」开关，暂停后一条采样都不做

## 一、面板

一页，五块内容：

| 区块 | 内容 | 口径 |
|---|---|---|
| 两个数字 | 「陪了你 X」+「你安静过 N 次，最长 Y」 | **分两行给出，绝不相加** |
| 24 小时时间轴 | 在场（蓝）/ 离开（灰）/ **没有记录**（浅灰底） | 关机、睡眠、插件没运行都不算「离开」 |
| 覆盖率说明 | 「记录完整 / 有 X% 的时间在记录 · Y 没有记录」 | 覆盖率低时界面主动解释自己 |
| 最近几天 | 每天一条覆盖率条 + 陪伴时长 | 一眼看见这一周 |
| 年历 | 一个月一块月历，左右箭头按月翻页，格子里是日期数字，颜色越深那天陪得越久 | 左边界是**初识日**（启动时向宿主记忆借一个日期，不是本插件第一条记录）；翻到开始记录之前，格子压淡成底纹并写「那时她还没开始数」 |

> **「安静」指这段时间没有键盘或鼠标操作，不是在断定你不在。**
> 唯一例外是锁屏：那是确认级判据，可以直说「你离开了」。

> **年历的左边界是「初识那天」，不是「开始记录那天」。**
> 它**不是写死的日期**：插件启动时会向宿主记忆借一个日子，只读最早一条对话的时间戳，
> 不读聊天内容（读法与边界见「隐私」一节）。证据优先级：最早对话 ＞ 记忆迁移种子 ＞
> 宿主初始化日 ＞ 本插件第一条记录 ＞ 今天；都拿不到就从今天开始数，**绝不编一个日期**。
> 借到的日子落进自己的 store，之后沿用且**只往前认、不往回跳** —— 用户清了记忆、
> 搬了机器、库被锁住，都不会把已经认定的历史抹掉。最多回追 36 个月。
> 想手动指定：settings 里设 `since_date`，它的优先级最高。

右上角是**暂停记录**开关。暂停后连键鼠空闲都不读，恢复后继续。
这是插件自己的隐私兜底，不依赖宿主隐私模式（原因见「隐私」）。

## 二、它不做什么

这些是设计，不是遗漏：

| 不做 | 为什么 |
|---|---|
| 不提醒、不弹窗、不推送 | 提醒类插件已经饱和，用户关掉的成本为零 |
| 不做打卡 | 记录是「痕迹」，不是「考核」 |
| 不给健康建议 | 只说事实，不做判断。「你昨天 02:40 还在」可以，「你该早点睡」不行 |
| 不读屏幕 / 摄像头 | 需要的精度不值得拿信任去换 |
| 不做输入控制 | 她只观察，不替你操作电脑或手机 |

在模型上下文里，她只暴露**一个只读查询工具**（`presence_today`），
其余入口全部对 Agent 隐藏。原因见「和 YUI 说话」。

### 2.1 协作约定：只被读，不反向依赖

这一节写给未来要和她配合的插件，也给市场审核看。

她只产出**只读的在场事实**——`presence_today` 的返回与面板 `presence_snapshot` 同源，
两边逐字一致。她不调度别人，不记忆别人的内容，也不因为别人的状态改动自己的判定。

方向是**单向的**：

| 谁 → 谁 | 允许 | 禁止 |
|---|---|---|
| 其他插件 → 本插件 | 读取 `presence_today`（陪伴 / 安静次数 / 最长安静 / 覆盖跨度） | 让本插件替它判断、替它发消息、替它改配置 |
| 本插件 → 其他插件 | **什么都不做** | 调用任何其他插件，或依赖任何其他插件存在 |

**为什么把这条写死**：单向依赖才能自由组合。一旦本插件开始读别人的状态来调整自己，
它就从「一个可拆卸的传感器」变成「依赖网里的一个结」——装上必须装全，卸载会连坐。
雏形阶段先定方向，后面接游戏、日程、番茄钟都不必改这里。

**接入方式**：对方不需要 `import` 本插件，只需在自己的工具说明里写
「若需知道用户是否真的在场，可调用 `presence_today`」。跨插件调用由宿主路由，
本插件不感知调用方是谁，也不为此增加任何入口。

**一条硬口径**：`companion_sec` 是「陪伴」，`covered_sec` 是「采样覆盖时长」，
`waiting_total_sec` 是「安静」。三者**不能相加，也不能互相替代**。
接入方若把 `covered_sec` 当陪伴用，就会复现 2026-11-01 那个「两小时四十一分」的错
（详见「和 YUI 说话」）。返回值里带 `guidance` 字段，照读即可，不要自行换算。

## 三、她观察什么

### 3.1 四个原始信号（Windows）

| 字段 | 名字 | 来源 API | 回答什么 |
|---|---|---|---|
| `w` | 键鼠空闲秒数 | `GetLastInputInfo` + `GetTickCount` | 距最后一次键盘/鼠标输入过了多久 |
| `q` | 通知状态码 | `SHQueryUserNotificationState` | 1=锁屏 · 2=全屏 · 3=全屏游戏 · 4=演示 · 5=普通桌面 · 6=刚进全屏 |
| `f` | 前台进程名 | `GetForegroundWindow` + `QueryFullProcessImageNameW` | **只取 exe 文件名**，不含路径与窗口标题 |
| `t` / `m` | 墙钟 / 单调时钟 | `time.time()` / `time.monotonic()` | 对齐日历 / 计算真实间隔 |

探针还会记录宿主快照的三个对照字段：

| 字段 | 含义 | 本机现状 |
|---|---|---|
| `p` | 宿主 `privacy_state` | 恒为 `unavailable` |
| `i` | 宿主 `system_idle_seconds` | 恒为 `None` |
| `c` | 宿主 `foreground_category` | 恒为空 |

> 本机的 `get_os_activity_snapshot()` 不可用（`os_signals_available=False`），
> 所以 Windows 上 `w/q/f` 是真正的主力，`p/i/c` 只作为将来宿主修好后的对照。

### 3.2 `w` 为什么可靠

`w = (GetTickCount() - dwTime) & 0xFFFFFFFF`，两个 32 位毫秒数直接相减：

- 它由系统维护，**插件重启、电脑睡眠都不会让它累积误差**
- 它是绝对量：判定「离开」的那一刻，`w` 已经是「从头到现在」的总时长
- 精度约 1 毫秒，而且空闲 4 小时与空闲 0.5 秒的精度一样

所以「你安静了多久」不需要逐秒累加，判定时直接读 `w` 即可。

## 四、跨端适配：她怎么在不同的设备上看见你

这一节对应《Agent 插件跨端输入适配方案：中断处理与事件抽象设计》的分层原则。
一句话：**业务逻辑不认识 Windows，也不认识手机；它只认识「语义」。**

### 4.1 三层结构

| 层 | 文件 | 职责 | 允许知道设备细节吗 |
|---|---|---|---|
| 底层 | `core/signals.py` | 读 Windows 原生信号（`ctypes`） | 是，所有 OS 差异关在这里 |
| 适配层 | `core/adapters.py` | 把不同来源归一成设备无关的 `Signal` | 是，**唯一**允许感知平台的地方 |
| 业务层 | `core/judge.py` / `core/state.py` | 判定六态、记账 | **否**，只读语义字段 |

适配层输出的 `Signal` 只回答三件事：

```
idle_sec   你多久没动了？（None = 这一路信号不可用）
screen     normal / locked / fullscreen / unknown
usable     这份数据足不足以做一次判定？
```

「屏幕态」是语义化的四态，不是 Windows 的 `q` 码。这样判定层就不需要知道
「2、3、6 代表全屏」这种平台知识——换到 Android / iOS / macOS，只要写一个新的
适配器，把当地的信号翻译成这四个词即可，`judge.py` 与 `state.py` 一行都不用改。

### 4.2 三种适配器与降级顺序

| 适配器 | 什么时候用 | 能提供什么 | 降级行为 |
|---|---|---|---|
| `Win32Adapter` | Windows 且 `ctypes` 可用 | 空闲秒数 + 锁屏/全屏 + 前台 exe | 原生失败时用宿主快照的 idle 兜底 |
| `HostSdkAdapter` | 非 Windows，或原生信号不可用 | 宿主快照的 idle / privacy / 前台分类 | 屏幕态只能是 `unknown`，判定退化为「只看空闲」 |
| `NullAdapter` | 两者都没有 | 什么都没有 | 不采样、不编造，面板显示「没有记录」 |

**隐私门控**：只要宿主明确说 `privacy_state == "private"`，适配器一个业务字段都不读，
直接返回不可用。`unavailable` 是「宿主自己拿不到信号」，不是用户的隐私指令，
本机正属于这种情况——所以它不阻止本地原生采样，否则这里会永远没有数据。

**不允许编造**：如果 `idle_sec` 和强语义屏幕态（锁屏/全屏）都拿不到，判定结果是
`unknown`，状态机立刻切断当前段。从「最后一条有效采样」到「下一条有效采样」
之间的时间不属于任何段——它在面板上就是浅灰色的「没有记录」。

> 为什么不直接监听硬件中断/输入钩子？
> 系统级输入钩子需要额外权限、会拉高安全风险，也容易和输入法、游戏反作弊冲突；
> 而本插件只需要「30 秒粒度」的在场判断，低频采样（文档 §5.1 允许的兜底方式）
> 已经足够。文档里的「输入注入」是给需要反向操作应用的 Agent 用的，她不操作，
> 所以这一块刻意不做。

## 五、怎么判断：六种状态 + 一种「不知道」

按优先级从上往下匹配（阈值是 `plugin.toml` 的默认值）：

| 状态 | 条件 | 含义 | 性质 |
|---|---|---|---|
| 锁屏 `locked` | `screen == locked` 且 `w ≥ 120` | 人确实不在 | **确认级** |
| 全屏长尾 `away_fullscreen` | `screen == fullscreen` 且 `w > 3h` | 画面还挂着，人已经走了 | 推断 |
| 全屏活动 `fullscreen` | `screen == fullscreen` 且 `w ≤ 3h` | 看片/游戏，人在屏幕前 | 观察事实 |
| 在操作 `interactive` | `w < 120` | 刚碰过键鼠 | 观察事实 |
| 短暂离席 `short_break` | `120 ≤ w ≤ 900` | 起个身、倒杯水 | 观察事实 |
| 静默离开 `away` | `w > 900` | 长时间无输入 | 推断 |
| **没有记录** `unknown` | 空闲与强屏幕态都不可用 | 这段时间什么都不知道 | **不猜** |

关键修正（都来自真机实测）：

1. **`screen == locked` 但 `w < 120`**：解锁瞬间 `q` 会滞后一个采样，
   此时判「在操作」，不判锁屏。
2. **全屏算陪伴**：人在屏幕前看片，她确实陪着；只有连续零输入超过 3 小时，
   才认定「画面挂着、人走了」。
3. **`q` 的 2/3/6 都算全屏**：2=全屏应用、3=全屏 D3D 游戏、6=刚进全屏的几秒。
   漏掉 6 会在刚切全屏的第一拍误判。
4. **`w is None` 不再默认「在操作」**：这是 v0.3.1 的修正。旧逻辑把
   「没有信号」当成「你在操作」，等于凭空生成陪伴时长；现在只在锁屏/全屏这类
   强语义下继续判定，其余一律 `unknown`。

两个阈值的含义：

- `interactive_sec = 120`：2 分钟内没动 = 还在看。设太紧会把「读长文、盯着屏幕思考、
  接个电话」踢出陪伴。
- `silent_leave_sec = 900`（T=15 分钟）：超过它才算一次值得记录的「安静」。
  它只决定「多长的安静值得被记一次」，**不影响时长准确性**——时长直接取当时的 `w`。

## 六、三本账：为什么数字不能相加

| 账本 | 字段 | 口径 | 回答什么 | 有缺口时 |
|---|---|---|---|---|
| **A 采样进度** | `covered_sec` / `span_sec` | 有采样的秒数 / 当天首尾跨度 | 数据完整吗 | 比值 < 1 |
| **B 互斥归因** | `companion_sec` / `away_sec` / `short_break_sec` / `locked_sec` | 每段 `duration` 之和 | 有采样的时间花在哪 | 不计 |
| **C 真实离开** | `waiting_sec` / `longest_wait_sec` / `waiting_count` | 段内 `peak_w` 的峰值 | 你实际离开了多久 | **照样准确** |

为什么不能并排相加：一次锁屏**同时**属于 B 的 `locked_sec` 和 C 的 `waiting`。
把「陪伴 9h · 安静 1.5h · 离席 0.5h · 锁屏 1.2h」加起来会超过一天，
数据立刻不可信。

几个容易混淆的符号：

| 符号 | 含义 | 为什么这样设计 |
|---|---|---|
| `duration` | 相邻采样间隔之和，**超过 120 秒的间隔会被丢弃** | 测「我真正看见你的时长」，不把睡眠/关机算进来 |
| `peak_w` | 一段里 `w` 的最大值 | 离开时长取「最后那一刻系统记的绝对空闲时长」，天然回溯，不重复累加 |
| `open_wait_sec` | 还没结束的那次离开的峰值 | 面板要实时显示「正在安静」，不能等回到陪伴才结算 |
| `waiting_count` | 一次完整离开事件 +1 | `short_break → away → locked` 是**同一次**离开，不能切一段算一次 |
| `MAX_STEP_SEC = 120` | 两条采样间隔超过 120 秒 = 断档 | 合盖、睡眠、插件重启都会造成跳变；断档处切段，缺口不属于任何状态 |
| `roll_segment_sec = 600` | 同一状态每 600 秒切一刀 | 日聚合只在段结算时落盘；不切的话连续 4 小时不切换状态会让面板一直显示旧值 |
| `span_sec` | 当天第一条到最后一条有效采样的墙钟差 | 覆盖率的分母；关机期间没有采样，但跨度照实包含 |
| `covered_ratio` | `covered_sec / span_sec` | 低于 95% 时面板会主动说「有 X% 的时间在记录」 |

## 七、文案口径：她只说事实

| 场景 | 可以说 | 不可以说 |
|---|---|---|
| 锁屏（确认级） | 「你离开了 X」 | — |
| 全屏 | 「你在看片子，她陪着」 | — |
| 静默（推断） | 「你安静了 X」 | ✗「她等了你 X」 |
| 没有信号 | 「这段没有记录」 | ✗「你一直在」 / ✗「你走了」 |

原因：窗口化看视频与真离开在数据上完全同形（实测看片 74 分钟 `w` 涨到 4488，
真离开 110 分钟涨到 6652），`q=5` 时无法区分。**数据层可以推断，文案层只能说事实。**

## 八、和 YUI 说话：为什么她的回答和面板一致

### 8.1 之前的 bug

2026-11-01 真机：用户问 YUI「陪了我多久」，YUI 回答「两小时四十一分」，
面板同时显示「1 小时 45 分」。回查发现 YUI 当时调用的是**另一个插件**的状态接口
（`forever_companion.get_status`），手里根本没有本插件的数据；「2h41」恰好是当天的
**有采样时长**（A 账本），不是陪伴时长（B 账本）。

### 8.2 修法：只给她一把尺子

新增唯一对模型可见的只读工具 `presence_today`（`@llm_tool`）：

- 数据源与面板完全相同：`_day_view()` + 同一套 `duration` 口径
- 返回的 `summary` 字段已经按面板口径写成整句，**模型照读即可**
- 同时给出精确字段，避免模型自己换算：
  `companion_sec`（陪伴）、`waiting_count`（安静次数）、`longest_wait_sec`（最长一次）、
  `span_sec`（跨度）、`window`（统计窗口，如 `10:57 – 14:48`）、
  `caveat`（记录起点提示，见下）
- 返回 `guidance` 明确写死：`companion_sec` 才是「陪了你」，
  `covered_sec` 只是「有采样时长」，三者不能相加；`caveat` 非空时必须一并说出

**`caveat` 是为什么加的。** 插件 10:57 才启动、`companion_sec` 只有 1 小时 45 分时，
模型很容易说成「今天只陪了你 1 小时 45 分」——听上去像她上午不在，
其实是那之前根本没有在记。所以首条采样晚于当日 00:30 时，
summary 里紧跟数字补一句「（从 10:57 开始记的）」，`caveat` 字段给出完整解释：

> 空白 ≠ 不在。这是本插件唯一一处主动「替自己辩解」的地方。

示例返回：

```json
{
  "summary": "今天到现在，她陪了你 3 小时 8 分（从 10:57 开始记的）；你安静过 1 次，最长 58 分钟。她今天最后一次见到你是 14:48。",
  "companion_sec": 11300.0,
  "waiting_count": 1,
  "longest_wait_sec": 3480.0,
  "span_sec": 13860.0,
  "coverage": 0.976,
  "window": "10:57 – 14:48",
  "caveat": "今天的记录是从 10:57 开始的，在那之前没有记录 —— 那是空白，不是她不在。",
  "guidance": "回答『陪了我多久』只用 companion_sec；covered_sec 是采样覆盖时长，waiting 是另一本账，三者不能相加。caveat 非空时必须把『记录从几点开始』一并说出，禁止把 companion_sec 说成『今天只陪了这么久』——窗口之前是没在记录，不是她不在。"
}
```

> 为什么只开一个工具：模型可见的工具越多，越容易在「该用哪个」上犯错，
> 也越占 Agent 路由的 prompt 预算。一个查询工具足够回答「陪了多久、安静几次、
> 几点来的」，其余入口继续对 Agent 隐藏。

---

## 九、隐私

- **采集白名单只有四个量**（`w/q/f/t`），没有第五个
- **全部本地存储**，无 HTTP 请求、无遥测、断网照常工作
- **不读**屏幕像素、窗口标题、键盘内容；前台进程只取 exe 文件名
- **自带暂停开关**：暂停后一条采样都不做，连键鼠空闲也不读
  - 为什么不依赖宿主隐私模式：本机 `privacy_state` 恒为 `unavailable`，
    那个保护永远不会触发，等于没有
- **宿主的隐私门控仍然尊重**：只要宿主明确说 `privacy_state != visible`，
  适配层直接返回不可用，一个业务字段都不读
- **一键清空**：`probe_clear`（需 `confirm=true`）
- 日聚合默认保留 730 天；原始采样 400 块 ≈ 66 小时

### 向记忆借的那个日期

年历的左边界（初识日）要从宿主记忆里读，这是本插件**唯一一处读取宿主数据**的地方。
边界写清楚：

| 项 | 具体做法 |
|---|---|
| 读什么 | 只查 `time_indexed.db` 的 `MIN(timestamp)`（一条时间戳），以及 `persona.json` 的 `migrated_at` |
| **不读什么** | `message` 列 —— 你和她说的话，一个字都不读；fact 的正文也不读 |
| 打开方式 | SQLite 一律 `mode=ro`，只读连接；不建表、不写文件、不修改任何数据 |
| 频率 | 只在启动时读一次（约 3ms），不参与 5 秒轮询 |
| 失败时 | 静默降级到其它证据或本插件第一条记录，不报错、不阻断采样 |
| 落盘 | 只把**一个日期**存进自己的 store（`since_v1`），不存任何内容 |

不读其他插件的记忆。`forever_companion` 之类的 `first_seen` 是**它自己的初装时间**
（本机实测 2026-10-29，而真实初识是 2026-06-19），拿它当起点会凭空抹掉四个月历史；
而且那会把本插件从「可拆卸的传感器」变成依赖网里的一个结 —— 与 §2.1 的约定相冲突。

## 十、已知限制

1. **关机 / 强杀时最多丢 10 分钟采样。** 关机不会触发 `shutdown` 生命周期，
   最后一次落盘缓冲随进程消失；窗口由 `flush_every`（20 条 × 30 秒）决定。
   正常停止插件不会丢。
2. **电脑重启后 `GetTickCount()` 与 `monotonic()` 双双归零**，跨关机的两段采样
   不能相减；靠 `gap = max(delta_m, t差)` 切断，切掉的空白**不计入任何时长**。
3. **插件不在跑就没有采样。** 要求 N.E.K.O 基本常开，否则面板会出现大片空白。
4. **关机 ≠ 离开。** 那段时间你可能在睡觉、上班、用别的设备。任何猜测都是编造，
   所以只标「没有记录」。
5. **`q=5` 时窗口化看视频会误判成离开。** 这是已接受的取舍（上摄像头的代价更大）。
6. **`f` 在人离开后停在旧值**，不能当「当前在做什么」用；`q` 在锁屏/解锁边界
   会滞后 ≤ 1 个采样（判定层已做一拍修正）。
7. **日聚合按段落盘，段不结束就不更新。** 同一状态每 `roll_segment_sec`（600 秒）
   切一刀，最多滞后 10 分钟；前端会把相邻同类段并成一条色带，看不出切口。
8. **非 Windows 平台只有宿主快照可用时，屏幕态只能是 `unknown`**：它能判断
   「在操作 / 短暂离席 / 静默离开」，但分不清「锁屏」与「全屏」。
   宿主补上对应信号后，只需新增一个适配器。
9. **没有任何信号时不会产生数据**：面板显示「没有记录」，而不是一条假的时间轴。
10. **面板上的分钟数向下取整**，最多比真实值早 59 秒（59 分 50 秒会显示「59 分钟」）。
    这是显示口径而不是取数误差：底层的 `duration` 与 `presence_today` 用的是同一套
    `_fmt_dur()`，聊天里的数字和面板不会互相打架。

## 十一、入口

除 `presence_today` 外，全部入口带 `agent_hidden` —— 聊天里随口说句话不会触发它们，
面板与命令面板仍然可以调用。

| 入口 | 对谁可见 | 作用 |
|---|---|---|
| `presence_today` | **LLM / YUI** | 回答「陪了多久、安静几次、几点来」；返回面板同口径的 `summary` |
| `presence_status` | 面板 / 命令面板 | 今日原始摘要（含 `covered_ratio`、`span_sec` 等派生量） |
| `presence_snapshot` | 面板 | 5 秒轮询用的完整快照，与 dashboard 同源 |
| `presence_pause` | 面板 | 暂停 / 恢复记录 |
| `segments_backfill` | 命令面板 | 用探针历史补齐时间轴（只填空白日期，不覆盖已有数据） |
| `probe_status` | 命令面板 | 采样是否在跑、已落多少块 |
| `probe_export` | 命令面板 | 导出最近 N 块原始采样（默认 12 块 ≈ 6 小时） |
| `probe_flush` | 命令面板 | 立刻把缓冲落盘 |
| `probe_clear` | 命令面板 | 清空全部数据（需 `confirm=true`） |

> 代码里的 `@ui.context(id="dashboard")` 是面板数据源；
> `@plugin_entry` 是命令面板/API 入口；`metadata={"agent_hidden": True}`
> 表示「不要暴露给模型路由」。这三者是不同的门，不是同一件事。

## 十二、安装

把整个 `neko_presence/` 目录放进宿主的**已安装插件目录**：

```
<数据根>/.neko-plugin-installations/plugins/neko_presence/
```

本机实测路径：`D:\nekomemory--YUI\N.E.K.O\.neko-plugin-installations\plugins\neko_presence\`

放好后重启 N.E.K.O，宿主会自动把它登记为 `channel:"manual"`，但**不会自动启动**——
需要在 Plugin Manager 里手动点一次启动，之后 `auto_start` 生效。

> ⚠️ 改代码后**必须在 UI 里停止→启动插件**才生效：宿主把插件加载进独立进程，
> 不重启跑的还是旧代码。

启动成功的日志：

```
neko_presence v0.7.0 started: probe=True interval=30s interact=120s paused=False T=900s fullscreen_tail=3.0h days=N chunks=M segs=K src=win32
```

`src` 是本次装载的适配器：`win32` = Windows 原生；`host_sdk` = 宿主快照；
`none` = 当前平台没有可用信号（插件会照常启动，但不记录）。

## 十三、存储

| key | 内容 | 保留 |
|---|---|---|
| `current_v1` | 当前段 + 未结算的离开事件峰值。**必须落盘**，否则重启后累计归零 | 1 份 |
| `daily_v1` | 按天聚合（`YYYY-MM-DD` → `DayStat`） | 730 天 |
| `marks_v1` | 里程碑：第一天、最长陪伴日、最长一次安静 | 永久 |
| `seg:<date>` | 当天的分段时间轴（时间轴的数据来源） | 90 天 |
| `probe_index` | 原始采样块索引 | — |
| `probe:<ts>-<seq>` | 一块原始采样（`flush_every` 条；v0.3.1 起多记 `sc` 语义屏幕态与 `src` 来源） | 400 块 ≈ 66 小时 |
| `settings` | 运行时覆盖（如 `paused`） | 1 份 |

旧探针块没有 `sc` / `src` 字段，回放时会自动回退到 `q` 码，不需要迁移数据。

## 十四、和市场上的邻居

市场里没有同定位插件（2026-11-01 全量 130 个核查，slug `neko_presence` 未被占用）：

| 邻居 | 它做什么 | 我们差在哪 |
|---|---|---|
| `catgirl_daily_planner` | 你手填计划 + 到点提醒 + 早安播报 | 它靠你填，我们靠你活；它的复盘没有真实素材 |
| `neko_diary` | 记录**她的**每日小事与心情 | 记她的心情，不记你的作息 |
| `forever_companion` | 相处统计：聊天轮数、热力图、月报 | 数的是说了几句话；你挂机 10 小时，它是 0，我们是 10 小时 |
| `mood_state` | 用挡位提示词给猫娘加精力/心情 | 状态是她的，不观察你的系统信号 |
| `sys_monitor` | CPU/内存/磁盘/电量异常提醒 | 硬件指标，与人的在场无关 |

一句话：**它记录你打算做什么，我们记录你实际在不在。它管意图，我们管痕迹。**

## 十五、开发

纯逻辑层不依赖 SDK，可以脱离宿主直接跑：

```bash
python -c "from core.adapters import build_adapter; print(build_adapter().source)"
python tests/test_judge.py      # 28 项：六态判定 + unknown 降级 + 语义屏幕态
python tests/test_state.py      # 61 项：区间管理 / 日聚合 / 离开事件合并 / 切段 / 断档
python tests/test_adapters.py   # 24 项：平台归一 / 隐私门控 / 降级路径
python tools/check_day.py <store.db>       # 日检
python tools/replay.py <store.db>          # 用历史采样重放状态机（只读）
```

分层（依赖方向从上到下，业务层不 import 任何 OS API）：

```
core/signals.py   原始系统信号（Windows ctypes）
      ↓
core/adapters.py  语义归一：idle_sec / screen / usable（唯一感知平台的地方）
      ↓
core/judge.py     纯函数判定：六态 + unknown
      ↓
core/state.py     段管理 / 日聚合 / 三本账
      ↓
__init__.py       SDK 编排：生命周期、定时器、Store、面板、LLM 工具
```

设计细节与判定口径的来源见 `DESIGN.md`；
跨端分层原则见《Agent 插件跨端输入适配方案：中断处理与事件抽象设计》。
